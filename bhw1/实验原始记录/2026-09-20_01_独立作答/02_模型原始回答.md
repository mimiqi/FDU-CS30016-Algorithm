下面给出一个可证明最优的精确算法。它枚举己方在每个可决策 tick 的所有合法联合攻击选择，并通过记忆化动态规划选择终局生命值最大的后继状态。

关键点：不能把“避免过量伤害”当作正确的贪心准则。击杀顺序会改变敌方后续的可攻击目标、站位与攻击时机；“暂缓攻击”也可能有价值。因此需要搜索所有合法决策。

## 状态表示

每个单位记录：

\[
(\text{alive}, H, cd, k)
\]

其中：

- \(H\)：当前生命值；
- \(cd\in\{0,1\}\)：剩余冷却，\(0\) 表示 Ready；
- \(k\)：该单位已向 \(G\) 移动的 tick 数。

不直接以浮点坐标作为记忆化键。因为每个单位只会沿初始位置到 \(G\) 的直线移动，位置可由 \(k\) 唯一恢复：

\[
p_i(k)=
\begin{cases}
G,& k\ge L_i\\
p_i(0)+\dfrac{2k}{\|G-p_i(0)\|}(G-p_i(0)),& k<L_i
\end{cases}
\]

其中：

\[
L_i=\left\lceil \frac{\|G-p_i(0)\|}{2}\right\rceil
\]

最后一步不足 2 时直接到达 \(G\)。死亡单位的位置、冷却可规范化为固定哨兵值。

由于每次伤害固定为 10，存活单位的生命值只可能为：

\[
55,45,35,25,15,5
\]

另加一个死亡状态。

定义状态 \(s\) 为全部己方和敌方单位的上述信息。令：

\[
DP(s)=\text{从状态 }s\text{ 出发可获得的最大终局己方总生命值}
\]

## 单 tick 状态转移

在状态 \(s\) 中，设一个 Ready 己方单位射程内有 \(q\) 个存活敌人。它的可选动作是：

- 攻击其中任意一个敌人；
- 暂缓攻击。

因此该单位至多有 \(m+1\) 个动作。所有 Ready 己方单位的选择组成一个联合动作 \(a\)。

```text
NEXT(s, a):
    读取 tick 开始时的单位位置、生命和冷却

    attacks = 空列表

    # 1. 己方按联合动作选择攻击
    对每个存活己方单位 f:
        若 f.Ready 且 a 指定攻击敌人 e:
            将 (f, e) 加入 attacks

    # 2. 敌方按固定规则选择攻击
    对每个存活敌方单位 e:
        若 e.Ready:
            candidates = e 射程内的存活己方单位
            若 candidates 非空:
                f = candidates 中距离最小者
                    若距离相同，选编号最小者
                将 (e, f) 加入 attacks

    # 3. 同时结算伤害
    对每个攻击 (u, v) in attacks:
        damage[v] += 10

    对每个存活单位 v:
        H[v] -= damage[v]

    删除所有 H[v] <= 0 的单位

    若己方全灭或敌方全灭:
        返回终局状态

    # 4. 更新冷却
    对每个仍存活单位 u:
        若 u 在 attacks 中作为攻击者:
            cd[u] = 1
        否则:
            cd[u] = max(0, cd[u] - 1)

    # 5. 根据死亡移除后的统一位置快照决定移动
    对每个仍存活且本 tick 未攻击的单位 u:
        若 u 射程内不存在存活敌方单位:
            k[u] = min(k[u] + 1, L[u])

    返回新状态
```

这里“敌方单位”指相对阵营；因此该移动逻辑同时适用于双方。

## 动态规划与决策恢复

```text
SOLVE(s):
    若 s 是终局状态:
        返回所有存活己方单位生命值之和

    若 memo[s] 已存在:
        返回 memo[s]

    bestValue = -∞
    bestAction = null

    对每个己方合法联合动作 a:
        s2 = NEXT(s, a)
        value = SOLVE(s2)

        若 value > bestValue:
            bestValue = value
            bestAction = a

    memo[s] = bestValue
    choice[s] = bestAction
    返回 bestValue
```

求出 `SOLVE(initialState)` 后，从初始状态开始反复读取 `choice[s]`，调用 `NEXT(s, choice[s])`，直到终局，即得到一条达到最优值的逐 tick 己方攻击决策序列。

对于没有目标、未 Ready 或死亡的己方单位，联合动作中不为其指定攻击；Ready 且有目标的单位可被指定为“等待”。

## 正确性证明

### 引理 1：`NEXT(s,a)` 与题目中的一个 tick 规则完全一致

`NEXT` 先基于 tick 开始前的状态确定所有攻击目标：己方使用输入的合法联合动作，敌方按最近距离和编号规则选择。

随后，它累积全部攻击伤害并同时结算，因此保留了同归于尽、同 tick 多人集火和过量伤害的规则。然后删除死亡单位，再更新冷却，最后从同一个移动前快照并行判断和执行移动。每一步的顺序均与题意一致，故转移准确。

### 引理 2：状态空间有限，且不会出现循环

每个单位的：

- 生命状态只有 7 种（6 种存活生命值加死亡）；
- 冷却只有 2 种；
- 移动计数 \(k\) 只会在 \(0,\ldots,L_i\) 中单调增加；
- 死亡后不会复活。

若某个 tick 发生攻击，至少一个仍存活目标受到正伤害，生命总量严格下降。

若没有攻击，则冷却不会增加；若存在可移动单位，至少一个移动计数增加；若也没有单位移动，则必有处于冷却中的敌方单位，其冷却会减少。否则双方已接触且存在 Ready 敌方单位，敌方本应发动攻击，矛盾。

因此非终局状态不可能回到自身，有限状态图是有向无环图，递归必然终止。

### 定理：`SOLVE(initialState)` 返回最优终局己方总生命值

对终局状态，`SOLVE` 直接返回题目定义的终局价值，正确。

对任一非终局状态 \(s\)，所有合法的己方联合动作均被枚举。根据引理 1，每个动作对应真实规则下唯一的后继状态 \(s'\)。根据无环性，可按状态图的逆拓扑顺序归纳：假设所有后继状态的 `SOLVE(s')` 都已返回其最优值，则取所有合法动作后继值的最大值，恰好就是从 \(s\) 出发的最优值。

因此 `SOLVE(initialState)` 最优；`choice` 中保存的动作沿途组成一条达到该最优值的合法决策序列。

## 复杂度

令 \(N=n+m\)，并令每个单位最多移动：

\[
L_i=\left\lceil \frac{\|p_i(0)-G\|}{2}\right\rceil
\]

状态数上界为：

\[
K=O\left(\prod_{i=1}^{N} 14(L_i+1)\right)
\]

其中 14 来自 7 种生命/死亡状态与 2 种冷却状态。这是保守上界，实际可达状态通常远少于它。

一个状态中，己方联合动作数至多为：

\[
(m+1)^n
\]

模拟一个动作需要扫描单位对、计算敌方最近目标，耗时：

\[
O(N^2)
\]

因此总时间复杂度为：

\[
O\left(K(m+1)^nN^2\right)
\]

空间复杂度为：

\[
O(KN)
\]

用于存储记忆化状态、最优动作和单位状态。另需 \(O(T)\) 保存最终输出的决策序列，其中 \(T\) 为该最优战斗过程的 tick 数。

在题设的 \(n,m\le 3\) 下，该指数级精确算法适合作为审计用基准解。就近攻击、优先残血、避免同 tick 过量伤害等都可作为加速搜索时的动作排序或启发式策略，但单独使用时均不具备全局最优保证。
