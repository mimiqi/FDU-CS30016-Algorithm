# RTS 单位目标选择优化：人工修正版

## 0. 对照算法：默认就近攻击

为了衡量大模型生成的集火算法是否确实带来收益，先定义一个不进行全局协调的默认算法。该算法与题目规定的敌方行为一致：每个己方单位只根据自己的当前位置独立选择目标。

对每个处于 Ready 状态的己方单位：

1. 找出射程内所有存活敌方单位；
2. 选择距离最近的敌方单位；
3. 若距离相同，则选择编号最小的单位；
4. 若射程内没有敌方单位，则本 tick 不攻击并继续向目标点移动；若单位尚未 Ready 但射程内存在敌人，则不能攻击，也不能移动。

```text
function ChooseTargetsByNearestEnemy(state):
    actions = empty map

    for each alive friendly unit i:
        if i is not Ready:
            actions[i] = wait
            continue

        candidates = all alive enemies j within range of i

        if candidates is empty:
            actions[i] = wait
        else:
            target = arg min over j in candidates of (
                distance(i, j),
                id[j]
            )
            actions[i] = attack target

    return actions
```

该算法的每个单位独立决策，不检查其他己方单位选择了谁，因此可能分散火力。设己方单位数为 `n`，敌方单位数为 `m`，直接枚举候选目标时，每个 tick 的时间复杂度为 `O(nm)`。

可视化程序将这个默认算法作为对照组；敌方在两种对局中始终采用同一套就近攻击规则。

## 1. 框架定位

本问题中，敌方行为和战斗状态转移完全确定，只有己方单位在每个攻击机会上的决策可控。因此，可以把整个战斗建模为一个有限状态上的最优决策问题：

- 状态记录当前战场信息；
- 动作表示己方本 tick 的攻击选择；
- 状态转移严格按照题目中的同时结算和移动规则执行；
- 终止状态的收益为己方存活单位的总生命值；
- 在所有合法动作序列中寻找最大收益。

在单位数量和属性范围尚未确定时，最稳妥的初步方案是采用“精确状态搜索 + 记忆化动态规划”。该方案可以保证得到最优结果，但最坏情况下具有指数级复杂度。后续确定数据规模后，再决定是否需要改用整数规划、近似算法或启发式搜索。

## 2. 状态表示

在 tick 开始时，用状态 `s` 表示完整战场信息：

```math
s=(F,E)
```

其中，`F` 和 `E` 分别表示当前存活的己方单位集合与敌方单位集合。

对每个存活单位 `i`，记录：

```math
(p_i,H_i,r_i)
```

- `p_i=(x_i,y_i)`：当前位置；
- `H_i`：当前生命值；
- `r_i`：在当前 tick 开始时，距离再次 Ready 还需等待的 tick 数。

冷却量 `r_i` 的取值规则如下：

- `r_i=0` 表示单位处于 Ready 状态；
- 若单位在当前 tick 攻击，则下一状态中的冷却量为 `max(c_i-1,0)`；
- 若单位在当前 tick 未攻击，则下一状态中的冷却量为 `max(r_i-1,0)`；
- `r_i` 不会小于 0。

例如，单位在 tick 0 攻击且 `c_i=10`，则 tick 1 开始时有 `r_i=9`，tick 9 开始时有 `r_i=1`，tick 10 开始时恢复为 `r_i=0`，与题目规则一致。

攻击力、护甲、攻击间隔、射程、移动速度和单位编号均为固定属性，不必重复放入动态状态。

由于每个单位始终沿初始位置到 `G` 的同一直线移动，实际实现时可以记录单位已经完成的移动 tick 数 `m_i`，并由 `m_i` 推导位置，而不直接把浮点坐标放入状态键。`m_i` 在单位到达 `G` 后不再增加，因此只有有限种取值。

如果生命值和伤害允许小数，应在题目中规定定点精度或改用有理数表示，避免使用近似浮点数判断两个状态是否相同。

## 3. 己方合法动作

对每个存活己方单位 `i`：

1. 若 `r_i>0`，该单位本 tick 不能攻击；
2. 若 `r_i=0`，但射程内没有存活敌人，该单位也不能攻击；
3. 若 `r_i=0` 且射程内存在合法目标，可以选择：
   - 攻击任意一个射程内的存活敌方单位；
   - 本 tick 暂不攻击。

设己方单位 `i` 当前有 `d_i` 个合法目标，则它最多有 `d_i+1` 个选择，其中额外的 1 表示不攻击。

一个 tick 的己方联合动作是所有可决策单位动作的笛卡尔积：

```math
\mathcal A(s)=\prod_{i\in R_F(s)}\bigl(T_i(s)\cup\{\text{wait}\}\bigr)
```

其中：

- `R_F(s)` 是当前处于 Ready 状态的己方单位集合；
- `T_i(s)` 是单位 `i` 当前可以攻击的敌方目标集合。

---

## 4. 敌方动作

敌方动作不产生搜索分支。

对每个处于 Ready 状态的存活敌方单位 `e`：

1. 找出其射程内所有存活己方单位；
2. 选择距离最近的单位；
3. 若距离并列，则选择编号最小的单位；
4. 如果不存在合法目标，则本 tick 不攻击并保持 Ready。

敌方选择必须根据当前 tick 伤害结算前的状态计算，不能受到同一 tick 中其他攻击结果的影响。

---

## 5. 单个 tick 的状态转移

给定当前状态 `s` 和己方联合动作 `a`，状态转移函数记为：

```math
s'=T(s,a)
```

转移过程严格按照以下顺序执行。

### 5.1 确定攻击

- 根据动作 `a` 确定所有己方攻击；
- 根据固定规则确定所有敌方攻击；
- 记录本 tick 发动攻击的单位集合及每次攻击的目标。

### 5.2 同时结算伤害

单位 `i` 对单位 `j` 的实际伤害为：

```math
\operatorname{damage}(i,j)=\max(0.5,D_i-A_j)
```

先累加每个目标在本 tick 收到的全部伤害，再统一扣除生命值：

```math
H_j'=H_j-\sum_{i\text{ attacks }j}\operatorname{damage}(i,j)
```

随后移除所有满足 `H_j'\le 0` 的单位。同一 tick 中死亡的单位已经确定的攻击仍然有效。

### 5.3 更新冷却

- 本 tick 发动攻击且仍存活的单位，在下一状态中令 `r_i=max(c_i-1,0)`；
- 本 tick 未发动攻击且仍存活的单位，在下一状态中令 `r_i=max(r_i-1,0)`；
- 已经 Ready 且没有攻击的单位继续保持 `r_i=0`。

实现时必须统一冷却更新的时间语义，并用 `c_i=10`、tick 0 攻击、tick 10 再次 Ready 的例子进行校验。

### 5.4 执行移动

若战斗尚未结束，则对所有本 tick 没有发动攻击且仍存活的单位重新检查其射程。只有射程内不存在存活敌方单位的单位才向共同目标点 `G` 移动；射程内存在敌方单位的单位保持原位。

```math
p_i'=p_i+\min\left(v_i,\operatorname{dist}(p_i,G)\right)
\frac{G-p_i}{\operatorname{dist}(p_i,G)}
```

当 `p_i=G` 时保持原位，不计算上式中的除法。

## 6. 目标函数与动态规划方程

若状态 `s` 已经结束战斗，则其价值为：

```math
V(s)=\sum_{i\in F(s)}H_i
```

其中 `F(s)` 是终止状态下仍然存活的己方单位集合。

对非终止状态，最优价值满足：

```math
V(s)=\max_{a\in\mathcal A(s)}V(T(s,a))
```

使用哈希表保存已经求得的 `V(s)`，当相同状态再次出现时直接返回缓存结果。

对于不会改变生命值、位置或冷却状态的纯等待自环，可以直接删除。该动作不会产生更优结果，只会无限重复同一个状态。题目已经假设战斗最终结束，因此删除这种无进展自环不会排除任何更优的有限战斗策略。

## 7. 基础伪代码

```text
function Solve(state s):
    s = Canonicalize(s)

    if IsTerminal(s):
        return SumFriendlyHealth(s)

    if memo contains s:
        return memo[s]

    enemyActions = DetermineEnemyActions(s)
    bestValue = -infinity

    for each friendlyJointAction a in EnumerateFriendlyActions(s):
        nextState = SimulateOneTick(s, a, enemyActions)

        if nextState == s:
            continue

        value = Solve(nextState)
        bestValue = max(bestValue, value)

    memo[s] = bestValue
    return bestValue
```

若还需要输出完整攻击策略，则额外记录：

```text
choice[s] = 使 V(s) 最大的动作 a
```

从初始状态开始不断读取 `choice[s]` 并执行状态转移，即可恢复一条最优策略。

## 8. 强制过程压缩

如果某个状态下没有任何己方单位可以作出攻击选择，则该 tick 不存在决策分支。此时可以直接模拟后续状态，直到出现以下事件之一：

- 某个己方单位 Ready 且射程内存在敌人；
- 某个单位进入或离开攻击范围；
- 某个单位发动敌方固定攻击；
- 某个单位死亡；
- 战斗结束。

这一优化不会改变搜索结果，只会压缩没有选择的连续 tick。

## 9. 初步剪枝策略

### 9.1 当前生命值上界

生命值不会恢复，因此任意状态的最优值都不会超过当前己方总生命值：

```math
V(s)\le\sum_{i\in F(s)}H_i
```

若该上界不超过当前已经找到的最好终局收益，可以停止搜索该分支。

### 9.2 启发式下界

先运行一种快速策略得到可行解，例如：

- 优先击杀下一次攻击时间最早的敌人；
- 在能够击杀时优先减少敌方存活单位数；
- 在效果相同的情况下减少过量伤害。

该策略得到的结果可作为当前最优下界，用于配合上界剪枝。启发式结果本身不替代精确搜索。

### 9.3 对称状态合并

若干单位具有相同固定属性、位置、生命值和冷却状态时，交换这些单位不会改变后续结果。可以把这些单位按统一顺序排列，避免重复搜索对称状态。

### 9.4 动作排序

优先搜索更可能产生高收益的动作：

1. 能立即击杀敌方单位的动作；
2. 能减少敌方下一轮攻击次数的动作；
3. 过量伤害较少的动作；
4. 使后续状态具有更高启发式估值的动作。

动作排序不改变正确性，但能更早获得较好的下界。

不能仅凭“当前过量伤害较大”删除一个动作，因为不同攻击者参与集火后会产生不同的冷却和位置状态。

## 10. 正确性证明框架

### 引理 1：状态具有充分性

给定所有存活单位的位置、生命值和冷却状态后，下一 tick 的合法动作、敌方选择、伤害、死亡和移动均可唯一确定。过去的决策不会通过其他未记录信息影响未来，因此该状态满足马尔可夫性。

### 引理 2：动作枚举具有完备性

对每个可决策的己方 Ready 单位，算法枚举了所有合法敌方目标以及暂不攻击的选择。所有单位选择的笛卡尔积覆盖了题目允许的全部己方联合动作。

### 引理 3：状态转移与题目规则一致

`SimulateOneTick` 在结算前确定双方攻击，统一累加并同时结算伤害，随后执行死亡判定、冷却更新和移动，因此生成的下一状态与题目定义完全一致。

### 定理：`Solve` 返回最优终局生命值

终止状态直接返回题目定义的目标值。对任意非终止状态，算法枚举全部合法动作，并递归求出每个动作对应下一状态的最优值，再取其中最大值。根据最优性原理，所得结果等于从该状态出发的全局最优终局生命值。因此，从初始状态调用 `Solve` 可得到题目要求的最优值。

## 11. 初步复杂度

设可达状态总数为 `|S|`，任一状态下己方联合动作数的最大值为 `B`，一次状态转移处理的单位总数为 `N`。使用记忆化搜索后，时间复杂度可写为：

```math
O(|S|\cdot B\cdot N)
```

空间复杂度为：

```math
O(|S|\cdot N)
```

其中：

```math
B\le\prod_{i\in R_F}(d_i+1)
```

因此该精确算法的最坏时间和空间复杂度通常都是指数级。它适合作为规模较小时的正确基线，也可以用于验证后续贪心算法或近似算法是否产生错误。

---

## 12. 后续需要根据数据范围决定的内容

在正式确定算法前，还需要补充：

- 双方单位数的最大值；
- 坐标、生命值和各项属性的范围与精度；
- 最大攻击间隔；
- 是否只输出最优值，还是输出完整策略；
- 是否允许指数级精确算法；
- 是否要求多项式时间近似算法；
- 测试数据是否包含大量同属性单位；
- 战斗结束假设在输入层面如何保证。

若单位总数很小，可以继续完善上述精确搜索；若单位数较大，则应考虑滚动时域搜索、混合整数规划、蒙特卡洛树搜索或带近似界的启发式方法。
