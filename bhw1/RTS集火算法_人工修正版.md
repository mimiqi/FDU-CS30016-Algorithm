# RTS 单位目标选择优化：人工修正版

本文直接审计[大模型版](./RTS集火算法_大模型版.md)中的“最低虚拟生命值优先”规则。保留攻击合法性、同时结算、冷却和遇敌停步规则，修正目标选择。默认就近攻击仅作对照；本版本不是把默认算法改名为人工修正版。

## 1. 大模型版究竟错在哪里

大模型版按 F1、F2……处理 Ready 单位，为每个攻击者选择射程内虚拟生命值最低的敌人。分配一次攻击后扣除虚拟生命值，后续攻击避开虚拟生命值已归零的敌人。

虚拟生命值可以记录同一 tick 的预分配伤害。但以下推理不成立：

> 优先消灭低生命敌人，就能尽快减少敌方存活数量，从而使己方终局生命值最大。

即使所有初始属性完全相同，接敌时间也可以不同，从而产生不同冷却。击杀一个本 tick 已经出手的敌人，不会取消其攻击；在另一个敌人下次出手前将其击杀，却能消除一轮伤害。是否让己方单位多活到一次攻击机会，也会改变后续总输出。

错误发生在“用当前生命值决定唯一目标，并将其他合法选择全部排除”这一步。虚拟生命值没有包含这种跨 tick 的收益比较。

## 2. 完全符合统一属性要求的反例

本反例替换此前使用不同血量、攻击力的反例。四个单位初始均为生命55、攻击10、护甲0、射程6、移速2、攻击间隔2 tick，且全部 Ready。

共同目标点 G=(0,0)，初始坐标如下：

| 单位 | 阵营 | 初始坐标 |
|---|---|---|
| F1 | 己方 | (-10,0) |
| F2 | 己方 | (-7,0) |
| E1 | 敌方 | (3,0) |
| E2 | 敌方 | (4.5,0) |

敌方始终就近攻击，距离相同时按编号。双方在攻击后同时结算伤害；移动资格使用死亡移除后的统一位置快照判断。所有允许移动的单位同时移动。下表 HP 均为该 tick 结算后的值，死亡记为0。

|---:|---|---|---|---|
| 0 | 无 | 无 | (55,55,55,55) | (-8,-5,1,2.5) |

| E2 | 55 | 0.5 | 1 | 本 tick 不能攻击 |

四个单位从此保持这些位置。E1 在奇数 tick 攻击，E2 在偶数 tick 攻击；己方采用下述两种策略时均在奇数 tick 攻击。

只需存在合法策略得到5，而原算法得到0，就足以反驳原算法的全局最优性；此反驳本身不依赖穷举程序。另有精确搜索和独立整数模拟均确认本输入最优值恰好为5。

## 3. 为什么这个错误有迷惑性

1. 初始属性完全相同，容易把敌人视为可互换，忽略位置造成的攻击时机差异。
2. “尽快击杀”符合直觉，但必须区分敌人是否已经完成本 tick 的攻击。
3. 虚拟生命值成功解决了同一 tick 的伤害分配问题，容易使人误以为它也解决了整场战斗的最优决策。
4. 基础对称演示中，大模型策略剩余25点生命，优于默认算法的0。这种局部成功不能代替对所有输入的证明。

## 4. 在原算法基础上怎样修正

保留原算法的合法目标计算和战斗转移函数。将“每次只选最低虚拟生命值目标”改为“比较所有合法联合动作对应的最优后续收益”。

原集火动作仍可作为第一个被搜索的候选，以尽早找到可行方案，但不能据此删除其他攻击或等待选项。不能简单改成“优先下次攻击更早的敌人”就声称全局最优；那仍需要新的证明。

精确版本也不能仅因虚拟生命值已经归零就删除攻击该目标的分支：主动攻击与等待可能造成不同的冷却和移动状态。实现中保留这些合法动作，只合并得到完全相同后继状态的分支。

## 5. 状态、动作与转移

固定初始输入后，状态为按原单位编号排列的数组。对每个存活单位保存：

- 当前生命值 H，取55、45、35、25、15、5；
- 已实际移动的 tick 数 q；
- 剩余冷却 r，取0或1。

死亡单位记为0，不再记录其位置和冷却。单位的初始坐标、阵营、属性和编号作为固定输入保存，不能因“对称”而随意交换编号：敌方并列距离时会读取编号。

设单位初始位置为 p0，目标为 G，初始距离为 d，最大移动次数 L=ceil(d/2)。当 d>0：

~~~math
p(q)=p_0+\min(1,2q/d)(G-p_0)
~~~

d=0 时位置始终为 G。这使状态键只需整数，不需要用浮点坐标哈希。

每个 Ready 己方单位的动作是其射程内任意存活敌人，或 wait。非 Ready 单位只有 wait。枚举这些选项的笛卡尔积，得到本 tick 的联合动作。

对一个联合动作，统一执行：

1. 在 tick 开始状态上确定己方攻击和敌方就近攻击。
2. 累加全部伤害并同时扣血，再移除死亡单位；死亡不取消本 tick 已经确定的攻击。
3. 更新存活单位冷却：攻击过的置1，其他减1且最低为0。
4. 若一方全灭，立即终止，不再移动。
5. 在死亡移除后的统一位置快照上筛出可移动单位，再同时更新位置。

## 6. 修正后的伪代码

~~~text
function Solve(s):
    if IsTerminal(s):
        return SumFriendlyHP(s)

    k = EncodeByOriginalUnitIDs(s)
    if memo contains k:
        return memo[k]

    bestValue = -infinity
    bestAction = null
    seenSuccessors = empty set

    # 原贪心动作只用于排序，不用于剪枝
    for a in [ChooseTargetsByFocusFire(s), all legal joint actions]:
        next = SimulateOneTick(s, a)
        nk = EncodeByOriginalUnitIDs(next)

        if nk == k or nk in seenSuccessors:
            continue
        add nk to seenSuccessors

        candidate = Solve(next)
        if candidate > bestValue:
            bestValue = candidate
            bestAction = a

    memo[k] = bestValue
    choice[k] = bestAction
    return bestValue
~~~

从初始状态反复读取 choice，即得到一条最优攻击序列。缓存和 choice 必须属于同一个初始输入，不能跨不同场景共用状态键。

参考实现为 [rts-core.js](./rts-core.js) 中的 createSolver。达到状态预算时程序明确报错，不把被截断的搜索结果声称为最优解。

## 7. 终止性与正确性证明

### 7.1 状态有限

单位生命值只减不增，存活时仅有6种值；冷却有2种值；移动计数在0到 L 之间。包括死亡状态，单位 i 最多有 1+12(L_i+1) 种动态状态。

### 7.2 状态转移不会形成非平凡环

定义非负整数三元组：

~~~math
K=\sum_i\lceil H_i/10\rceil,\qquad
M=\sum_{i\text{ alive}}(L_i-q_i),\qquad
C=\sum_{i\text{ alive}}r_i
~~~

比较顺序为先 K、再 M、最后 C：

- 只要发生攻击，至少一个存活目标的生命值下降，K 严格下降。
- 没有攻击但发生移动时，K 不变，M 严格下降。
- 没有攻击也没有移动但冷却尚未归零时，K、M 不变，C 严格下降。
- 若三者均不变，则是纯自环，可跳过。合法同属性非终止输入实际上不会永久陷入这种状态：若有敌方在射程内且 Ready，它必须攻击；若没有双方接敌，未到 G 的单位必须移动；若都在 G，敌方也必须攻击。

因此，去掉自环后每次递归都进入字典序更小的状态，有限递归必然终止。

进一步，初始 K=6N，所以发生攻击的 tick 最多6N个；含移动的 tick 最多 sum L_i 个。其余只等待冷却的 tick，在攻击间隔为2时每次至多一个，总数不超过6N。因此一条战斗轨迹的 tick 数不超过 12N+sum L_i。这是宽松上界，不是平均时长估计。

### 7.3 最优性

状态保存了确定后续所有合法动作和转移所需的信息，具有充分性。动作枚举包含每个 Ready 单位的所有合法攻击和等待选项，因此具有完备性。

终止状态返回实际己方剩余生命值。对任意非终止状态，假设所有更小状态的值均已正确求得，算法枚举每个合法联合动作，求其后继状态最优值并取最大。因此：

~~~math
V(s)=\max_{a\in A(s)}V(T(s,a))
~~~

等于从 s 出发能够获得的最大终局生命值。由上述良基顺序归纳，初始状态的返回值也是全局最优。相同后继状态去重不会改变可取得的结果集合。

## 8. 复杂度推导

设己方 n 个单位，敌方 m 个单位，N=n+m；可达状态数为 S，单个状态最多 B 个合法联合动作。

~~~math
B\le(m+1)^n
~~~

其中 +1 表示 wait；不 Ready 或射程不够会减少实际分支数。状态总数可粗略上界为：

~~~math
S\le\prod_{i=1}^{N}\bigl(1+12(L_i+1)\bigr)
~~~

朴素实现中，敌方就近选择和移动阶段的范围检查需要两两检查单位，单次状态转移为 O(N^2)。每个非终止状态只求解一次，每个动作需要一次转移和缓存查询，因此在单位代价算术及哈希表平均常数查询模型下：

~~~math
T=O(SBN^2)
~~~

原框架把一次转移写成 O(N)，漏算了范围和最近目标检查；本版本已修正。几何运算按单位代价计，若分析精确代数数的位复杂度，必须另计运算开销。

缓存状态和一个最佳动作需 O(SN) 空间。当前实现还保留递归栈及每层的后继去重集合，若最大递归深度为 D：

~~~math
Space=O(SN+DBN)
~~~

其中 D 不超过 12N+sum L_i。该算法明确允许指数规模搜索，不将其称为高效的通用大规模方案。理论保证针对完整搜索；默认程序预算只保证两个内置小场景已算完。
