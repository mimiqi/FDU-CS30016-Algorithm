## 摘要

本实验研究确定性 RTS 战斗中的目标选择优化：双方单位初始属性完全相同，敌方就近攻击，己方选择攻击目标或等待，以最大化终局剩余生命值。被审计算法通过虚拟生命值协调集火，优先攻击当前最容易击杀的敌人，并主张这样可以保证全局最优。

本文构造一个仅含两名己方和两名敌方单位的反例。贪心算法最终剩余生命值为0，而改变击杀顺序的合法策略可以保留5点生命值。错误在于用当前生命值替代对未来攻击时机的比较：先击杀已经在本 tick 出手的敌人，可能错失阻止另一名敌人下一 tick 攻击的机会。人工修正版保留原战斗规则和集火动作，改为枚举全部合法联合动作并进行记忆化搜索；本文给出其终止性、最优性与复杂度分析。

## 1. 问题定义

### 1.1 输入与共同属性

输入为己方数量 n、敌方数量 m、共同移动目标 G 以及双方初始坐标。每方1至3个单位，编号分别为 F1,…,Fn 和 E1,…,Em；同阵营编号按整数比较。所有输入坐标分量在[-30,30]内，且为0.5的整数倍。

| 属性 | 己方与敌方统一数值 |
|---|---:|
| 初始生命值 | 55 |
| 单次攻击伤害 | 10 |
| 护甲 | 0 |
| 射程 | 6 |
| 每 tick 最大移动距离 | 2 |
| 攻击间隔 | 2 tick |
| 初始状态 | 全部 Ready |

战场是二维欧氏平面，单位视为点，允许重叠。没有碰撞、障碍、技能、随机伤害、治疗、弹道或其他额外机制。双方单位始终沿当前位置到 G 的直线移动，不越过 G。

### 1.2 攻击、冷却与移动规则

一个单位可攻击距离不大于6的存活敌人，射程边界包含在内。己方 Ready 单位可以攻击任意合法目标，也可以等待；等待保留 Ready 状态。敌方 Ready 且有合法目标时必须立即攻击最近的己方单位，距离相同取编号最小者。

第 t 个 tick 攻击后，下一次最早在 t+2 攻击。每个 tick 按以下顺序处理：

1. 在 tick 开始状态中确定双方全部攻击目标。
2. 累加伤害并同时扣血，再移除生命值不大于0的单位。本 tick 被击杀的单位，其已确定攻击仍然生效。
3. 若任一方全灭，战斗立即结束；同时全灭时己方收益为0。
4. 更新存活单位的下一 tick 冷却：本 tick 攻击过的设为1，其余减1且最低为0。
5. 在死亡移除后、任何单位移动前的统一位置快照中判断移动资格。本 tick 没攻击、尚未到 G 且射程内没有存活敌人的单位前进 min(2,到 G 的距离)，所有移动同时生效。

只要射程内有存活敌人，单位就停下，包括尚在冷却或主动等待的情况。移动后首次进入射程，从下一 tick 才判断攻击；不在移动中途截停或插入攻击。

### 1.3 输出与优化目标

输出最优终局己方总生命值，以及实现该值的一条逐 tick 合法攻击决策序列：

~~~math
V=\sum_{i\in\text{终局己方存活单位}} H_i,
\qquad\text{目标为}\ \max V.
~~~

允许指数级精确算法，不预设存在多项式时间最优解法。完整条目版规则见[题干](./RTS集火算法_题干.md)；本节是便于阅读的等价整理，不代替早期实验实际发送的提示词。

## 2. 模型算法与待审计主张

### 2.1 算法整理

旧模型使用“最低虚拟生命值优先”的集火规则。每个 tick 复制敌方实际生命值，按己方编号依次为 Ready 单位分配目标：

~~~text
ChooseTargetsByFocusFire(state):
    对每个存活敌人 e:
        virtualHP[e] = HP[e]
    actions = 空映射

    按编号从小到大遍历存活己方单位 f:
        若 f 尚未 Ready:
            actions[f] = wait
            continue

        candidates = 射程内所有存活且 virtualHP > 0 的敌人
        若 candidates 为空:
            actions[f] = wait
            continue

        e = candidates 中 (virtualHP[e], HP[e], 编号[e]) 最小者
        actions[f] = attack(e)
        virtualHP[e] = max(0, virtualHP[e] - 10)

    return actions
~~~

虚拟血量只用于分配攻击，不提前修改真实血量。所有已分配攻击仍在同一 tick 同时结算。单次目标选择的时间复杂度为 O(nm)，额外空间为 O(n+m)。

### 2.2 正确性说明中的关键主张

[旧模型回答整理稿](./RTS集火算法_大模型版.md)中的论证可概括为：

> 先集火生命值最低的敌人，可以更早完成击杀；敌人越少，未来伤害越低；每轮重复这一选择，就能最大化己方终局生命值。

这里第一步关于局部伤害利用的直觉，并不足以推出最后的全局最优结论。下文用一个合法输入和一条收益更高的合法策略反驳它。

## 3. 具体反例与逐 tick 推导

四个单位初始均为生命55、攻击10、护甲0、射程6、移速2、攻击间隔2 tick，且全部 Ready。

共同目标点 G=(0,0)，初始坐标如下：

| 单位 | 阵营 | 初始坐标 |
|---|---|---|
| F1 | 己方 | (-10,0) |
| F2 | 己方 | (-7,0) |
| E1 | 敌方 | (3,0) |
| E2 | 敌方 | (4.5,0) |

敌方始终就近攻击，距离相同时按编号。双方在攻击后同时结算伤害；移动资格使用死亡移除后的统一位置快照判断。所有允许移动的单位同时移动。下表 HP 均为该 tick 结算后的值，死亡记为0。

### 3.1 相同的开局：tick 0—2

| tick | 己方攻击 | 敌方攻击 | 结算后 HP：(F1,F2,E1,E2) | 移动后 x 坐标 |
|---:|---|---|---|---|
| 0 | 无 | 无 | (55,55,55,55) | (-8,-5,1,2.5) |
| 1 | F2→E1 | E1→F2 | (55,45,45,55) | (-6,-5,1,0.5) |
| 2 | 无 | E2→F2 | (55,35,45,55) | (-4,-5,1,0.5) |

tick 1 开始时，F2 与 E1 距离为6，因此互相攻击。E2 距离 F2 为7.5，尚未接敌，继续移动到0.5。tick 2 时 E2 首次攻击；E1、F2 正在冷却；F1 因射程内仍没有敌人，继续移动到-4。

到 tick 3 开始时：

| 单位 | 生命值 | 位置 x | 剩余冷却 | 可以攻击谁 |
|---|---:|---:|---:|---|
| F1 | 55 | -4 | 0 | E1、E2 |
| F2 | 35 | -5 | 0 | E1、E2 |
| E1 | 45 | 1 | 0 | 选择更近的 F1 |
| E2 | 55 | 0.5 | 1 | 本 tick 不能攻击 |

四个单位从此保持这些位置。E1 在奇数 tick 攻击，E2 在偶数 tick 攻击；己方采用下述两种策略时均在奇数 tick 攻击。

### 3.2 大模型策略：最终生命值0

tick 3，E1 的实际和虚拟生命值均比 E2 低，因此两名己方单位都攻击 E1。

| tick | 己方攻击 | 敌方攻击 | 结算后 HP：(F1,F2,E1,E2) |
|---:|---|---|---|
| 3 | F1→E1，F2→E1 | E1→F1 | (45,35,25,55) |
| 4 | 无 | E2→F1 | (35,35,25,55) |
| 5 | F1→E1，F2→E1 | E1→F1 | (25,35,5,55) |
| 6 | 无 | E2→F1 | (15,35,5,55) |
| 7 | F1→E1，F2→E2 | E1→F1 | (5,35,0,45) |
| 8 | 无 | E2→F1 | (0,35,0,45) |
| 9 | F2→E2 | 无 | (0,35,0,35) |
| 10 | 无 | E2→F2 | (0,25,0,35) |
| 11 | F2→E2 | 无 | (0,25,0,25) |
| 12 | 无 | E2→F2 | (0,15,0,25) |
| 13 | F2→E2 | 无 | (0,15,0,15) |
| 14 | 无 | E2→F2 | (0,5,0,15) |
| 15 | F2→E2 | 无 | (0,5,0,5) |
| 16 | 无 | E2→F2 | (0,0,0,5) |

tick 7，虚拟生命值避免了第二发继续打 E1，但并未挽救错误的击杀顺序。F1 在 tick 8 死亡，失去了 tick 9 的攻击机会。

### 3.3 改变集火对象：最终生命值5

保持 tick 0—2 的全部行为，从 tick 3 起优先集火生命值较高的 E2，击杀后再攻击 E1。

| tick | 己方攻击 | 敌方攻击 | 结算后 HP：(F1,F2,E1,E2) |
|---:|---|---|---|
| 3 | F1→E2，F2→E2 | E1→F1 | (45,35,45,35) |
| 4 | 无 | E2→F1 | (35,35,45,35) |
| 5 | F1→E2，F2→E2 | E1→F1 | (25,35,45,15) |
| 6 | 无 | E2→F1 | (15,35,45,15) |
| 7 | F1→E2，F2→E2 | E1→F1 | (5,35,45,0) |
| 8 | 无 | 无 | (5,35,45,0) |
| 9 | F1→E1，F2→E1 | E1→F1 | (0,35,25,0) |
| 10 | 无 | 无 | (0,35,25,0) |
| 11 | F2→E1 | E1→F2 | (0,25,15,0) |
| 12 | 无 | 无 | (0,25,15,0) |
| 13 | F2→E1 | E1→F2 | (0,15,5,0) |
| 14 | 无 | 无 | (0,15,5,0) |
| 15 | F2→E1 | E1→F2 | (0,5,0,0) |

tick 7 击杀 E2，消除了它在 tick 8 的攻击。F1 因而活到 tick 9，即使当场死亡，已确定的攻击仍然有效，额外对 E1 造成10点伤害。

只需存在合法策略得到5，而原算法得到0，就足以反驳原算法的全局最优性；此反驳本身不依赖穷举程序。另有精确搜索和独立整数模拟均确认本输入最优值恰好为5。

## 4. 错误发生的位置及其迷惑性

错误发生在选择唯一目标的这一步：算法把当前虚拟生命值最低的敌人直接当作全局最优目标，排除了其他合法选择，但没有证明这种贪心选择可以延伸为整场战斗的最优决策。

反例中 tick 3 两名敌人的攻击力和射程相同，却处在不同冷却阶段。E1 在奇数 tick 攻击，E2 在偶数 tick 攻击。tick 7 击杀 E1 无法取消它在当前 tick 已经确定的攻击；同一 tick 击杀 E2，则可以阻止它在 tick 8 的攻击。后者让 F1 多活到 tick 9，额外造成10点伤害，从而改变最终胜负。

两条策略都在 tick 7 完成第一次击杀，但终局收益不同。因此，仅比较当前敌人数或第一次击杀时间仍然不够，还需考虑攻击时机、被保护单位的下一次攻击以及后续目标变化。

这一错误具有合理的迷惑性：

1. 双方初始属性完全相同，容易忽略初始位置造成的接敌时间和冷却差异。
2. 虚拟生命值确实能够减少某些同 tick 过量伤害，容易被误认为同时解决了全局目标选择。
3. 在基础演示中，贪心策略剩余25点生命，优于就近攻击的0；单个成功例子容易被误推成普遍结论。
4. “敌人越少，伤害越低”省略了“哪个敌人、何时攻击、正在攻击谁”的条件，无法支撑交换论证或贪心选择性质。

## 5. 人工修正：保留原框架，修正选择规则

保留原算法的合法目标计算和战斗转移函数。将“每次只选最低虚拟生命值目标”改为“比较所有合法联合动作对应的最优后续收益”。

原集火动作仍可作为第一个被搜索的候选，以尽早找到可行方案，但不能据此删除其他攻击或等待选项。不能简单改成“优先下次攻击更早的敌人”就声称全局最优；那仍需要新的证明。

精确版本也不能仅因虚拟生命值已经归零就删除攻击该目标的分支：主动攻击与等待可能造成不同的冷却和移动状态。实现中保留这些合法动作，只合并得到完全相同后继状态的分支。

### 5.1 状态、动作与转移

固定初始输入后，状态为按原单位编号排列的数组。对每个存活单位保存：

- 当前生命值 H，取55、45、35、25、15、5；
- 已实际移动的 tick 数 q；
- 剩余冷却 r，取0或1。

死亡单位记为0，不再记录其位置和冷却。单位的初始坐标、阵营、属性和编号作为固定输入保存，不能因“对称”而随意交换编号：敌方并列距离时会读取编号。

设单位初始位置为 p0，目标为 G，初始距离为 d，最大移动次数 L=ceil(d/2)。当 d>0：

~~~math
p(q)=p_0+\min(1,2q/d)(G-p_0)
~~~

d=0 时位置始终为 G。这使状态键只需整数，不需要用浮点坐标哈希。

每个 Ready 己方单位的动作是其射程内任意存活敌人，或 wait。非 Ready 单位只有 wait。枚举这些选项的笛卡尔积，得到本 tick 的联合动作。

对一个联合动作，统一执行：

1. 在 tick 开始状态上确定己方攻击和敌方就近攻击。
2. 累加全部伤害并同时扣血，再移除死亡单位；死亡不取消本 tick 已经确定的攻击。
3. 更新存活单位冷却：攻击过的置1，其他减1且最低为0。
4. 若一方全灭，立即终止，不再移动。
5. 在死亡移除后的统一位置快照上筛出可移动单位，再同时更新位置。

### 5.2 修正后的伪代码

~~~text
function Solve(s):
    if IsTerminal(s):
        return SumFriendlyHP(s)

    k = EncodeByOriginalUnitIDs(s)
    if memo contains k:
        return memo[k]

    bestValue = -infinity
    bestAction = null
    seenSuccessors = empty set

    # 原贪心动作只用于排序，不用于剪枝
    for a in [ChooseTargetsByFocusFire(s), all legal joint actions]:
        next = SimulateOneTick(s, a)
        nk = EncodeByOriginalUnitIDs(next)

        if nk == k or nk in seenSuccessors:
            continue
        add nk to seenSuccessors

        candidate = Solve(next)
        if candidate > bestValue:
            bestValue = candidate
            bestAction = a

    memo[k] = bestValue
    choice[k] = bestAction
    return bestValue
~~~

从初始状态反复读取 choice，即得到一条最优攻击序列。缓存和 choice 必须属于同一个初始输入，不能跨不同场景共用状态键。

参考实现为 [rts-core.js](./rts-core.js) 中的 createSolver。达到状态预算时程序明确报错，不把被截断的搜索结果声称为最优解。

### 5.3 终止性与正确性证明

#### 状态有限

单位生命值只减不增，存活时仅有6种值；冷却有2种值；移动计数在0到 L 之间。包括死亡状态，单位 i 最多有 1+12(L_i+1) 种动态状态。

#### 状态转移严格下降

定义非负整数三元组：

~~~math
K=\sum_i\lceil H_i/10\rceil,\qquad
M=\sum_{i\text{ alive}}(L_i-q_i),\qquad
C=\sum_{i\text{ alive}}r_i
~~~

比较顺序为先 K、再 M、最后 C：

- 只要发生攻击，至少一个存活目标的生命值下降，K 严格下降。
- 没有攻击但发生移动时，K 不变，M 严格下降。
- 没有攻击也没有移动但冷却尚未归零时，K、M 不变，C 严格下降。
- 三者不可能在非终局转移中均不变：没有攻击也没有实际移动时，必有双方接敌；否则未到 G 的单位应移动，全部到 G 也会相互接敌。接敌的敌方若 Ready 就必须攻击，所以此时至少一个敌方正在冷却，C 必定下降。

因此每次递归都进入字典序更小的状态，有限递归必然终止。伪代码中的自环过滤只是防御性检查；在本题合法非终止状态中不会遇到自环。

进一步，初始 K=6N，所以发生攻击的 tick 最多6N个；含移动的 tick 最多 sum L_i 个。其余只等待冷却的 tick，在攻击间隔为2时每次至多一个，总数不超过6N。因此一条战斗轨迹的 tick 数不超过 12N+sum L_i。这是宽松上界，不是平均时长估计。

#### 最优性

状态保存了确定后续所有合法动作和转移所需的信息，具有充分性。动作枚举包含每个 Ready 单位的所有合法攻击和等待选项，因此具有完备性。

终止状态返回实际己方剩余生命值。对任意非终止状态，假设所有更小状态的值均已正确求得，算法枚举每个合法联合动作，求其后继状态最优值并取最大。因此：

~~~math
V(s)=\max_{a\in A(s)}V(T(s,a))
~~~

等于从 s 出发能够获得的最大终局生命值。由上述良基顺序归纳，初始状态的返回值也是全局最优。相同后继状态去重不会改变可取得的结果集合。

## 6. 时间与空间复杂度

设己方 n 个单位，敌方 m 个单位，N=n+m；可达状态数为 S，单个状态最多 B 个合法联合动作。

~~~math
B\le(m+1)^n
~~~

其中 +1 表示 wait；不 Ready 或射程不够会减少实际分支数。状态总数可粗略上界为：

~~~math
S\le\prod_{i=1}^{N}\bigl(1+12(L_i+1)\bigr)
~~~

朴素实现中，敌方就近选择和移动阶段的范围检查需要两两检查单位，单次状态转移为 O(N^2)。每个非终止状态只求解一次，每个动作需要一次转移和缓存查询，因此在单位代价算术及哈希表平均常数查询模型下：

~~~math
T=O(SBN^2)
~~~

单次转移包含两两范围及最近目标检查，不能只按一次线性扫描估计。几何运算按单位代价计，若分析精确代数数的位复杂度，必须另计运算开销。

缓存状态和一个最佳动作需 O(SN) 空间。当前实现还保留递归栈及每层的后继去重集合，若最大递归深度为 D：

~~~math
Space=O(SN+DBN)
~~~

其中 D 不超过 12N+sum L_i。该算法明确允许指数规模搜索，不将其称为高效的通用大规模方案。理论保证针对完整搜索；默认程序预算只保证两个内置小场景已算完。

## 8. 结论

最低虚拟生命值优先是一种具有直觉合理性的启发式策略，但不满足本题的全局最优要求。反例表明，即使所有单位初始属性相同，也可能因冷却时机和击杀顺序不同，使贪心策略全灭，而另一条合法策略保留5点生命值。

人工修正版保留原有战斗模型，将单一贪心选择改为对全部合法联合动作的比较，并用有限状态上的动态规划保证最优。审计的关键在于区分“局部伤害分配合理”与“能够证明终局目标最优”。
