# 任务二后续候选：共享预算的深度优先递归

## 完整题目

n=2^h，h>=2。采用单位代价 RAM 模型，所有整数操作及 work() 均为 O(1)。预算是本次 Main 中所有 Visit 调用共享的同一个可变变量，不复制、不回滚。递归顺序按代码顺序执行；没有并行、缓存或记忆化。

```text
procedure Main(n):
    budget = floor(n / log2(n))
    Visit(n)

procedure Visit(m):
    for i = 1 to m:
        work()
    if m == 1:
        return
    Visit(m / 2)
    if budget > 0:
        budget = budget - 1
        Visit(m / 2)
```

问题：Main(n) 的紧确渐近时间复杂度是什么？给出推导。

## 独立结论：Θ(n)

令 b=floor(n/h)。先考虑完整二叉递归树：根规模 n，第 d 层每个节点规模 s_d=n/2^d，叶子从左至右排列。实际程序按深度优先顺序访问；每次开启右子树消耗一个预算，左子树总会先执行。

初始左链抵达第一个叶子；每次消耗一个预算进入右子树，其后无条件左链一定能抵达下一个叶子。没有预算时，所有待执行的右子树被跳过。故程序恰好访问最左侧 b+1 个叶子及其祖先，没有跳过前面的叶子去访问后面的叶子。

每个第 d 层节点覆盖 s_d 个连续叶子，所以实际访问节点数恰为 ceil((b+1)/s_d)。精确 work 次数为：

W(n)=Σ[d=0..h] s_d · ceil((b+1)/s_d)。

利用 ceil(x)<=x+1：

W(n)<=Σ[d=0..h] (b+1+s_d)

<=(h+1)(b+1)+2n=O(n)。

最后一步用 b=floor(n/h)，且 h=log2 n=O(n)。根节点就调用 n 次 work，因此 W(n)>=n，得到 Θ(n)。递归调用、分支与循环控制开销均被 W(n) 的常数倍界定，总时间同样为 Θ(n)。

## 可能出现的误判

- 看见两次 Visit(m/2) 就套 T(m)=2T(m/2)+Θ(m)，漏掉共享预算和实际执行顺序。
- 将总预算视为每个调用各自拥有，错误复制全局状态。
- 用访问节点总数乘根节点的 n，忽略深层节点规模减小。
