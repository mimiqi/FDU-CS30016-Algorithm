## 3. 新回答的正确性检查

原文见[模型原始回答](../实验原始记录/2026-09-20_01_独立作答/02_模型原始回答.md)。以下解释属于审计者的分析，不改写原文。

### 状态是否遗漏信息

固定一次输入并保留单位编号后，生命值、冷却、移动次数足以决定未来。单位沿初始点到共同目标点的直线前进，每次移动2，最后一次截到目标点；暂停只改变何时移动，不改变第 k 次移动后的位置。

所以使用移动次数恢复坐标成立。初始点就在目标点时，L=0，直接取位置G，不会执行除以距离0的分支。时间本身不参与任何额外规则，故无需把绝对 tick 加入状态。死亡单位不会复活，可以统一为哨兵状态。

### 状态转移是否符合规则

原文依次确定双方攻击、累加伤害、同时扣血、移除死亡者、更新冷却、判断移动。攻击列表在死亡判定之前确定，保留了本 tick 被击杀单位的攻击。移动注释和正确性证明都明确使用统一快照，因此应按先判定、后同时移动的语义理解。

联合动作包含每个 Ready 己方单位的所有合法目标以及等待，没有用虚拟生命值排除攻击分支，也没有未经证明地强制立即攻击。这避开了旧稿的关键错误。

### 递归会不会成环

令死亡单位生命值取0，定义非负整数三元组：

```math
Q=\sum_i\lceil H_i/10\rceil,\qquad
M=\sum_{i\text{ alive}}(L_i-k_i),\qquad
C=\sum_{i\text{ alive}}cd_i.
```

按 Q、M、C 的顺序进行字典序比较：

1. 有攻击时，合法目标在 tick 开始时存活，且至少受到10点伤害，Q严格下降。目标被本次攻击击杀仍然算下降。
2. 没有攻击但有实际移动时，Q不变，M严格下降。
3. 没有攻击也没有实际移动时，至少存在一对相互在射程内的双方单位：否则尚未到G的单位应移动；若所有单位都在G，则已经相互在射程内。此时接敌的敌方若Ready就必须攻击，所以它必然在冷却，C严格下降。

因此每个非终局转移均严格下降，有限状态图没有环。原文的终止性论证可按这个字典序严格化，没有发现需要反例推翻的漏洞。

初始Q=6N。有攻击的 tick 至多6N个，含实际移动的 tick 至多 sum L_i 个；其余纯等待 tick 每次最多1个，并可对应之前的一次攻击。因此总 tick 数有宽松上界 12N+sum L_i。若所有输入坐标分量均在[-30,30]，每个 L_i 至多43，N至多6，上界为330。

### 是否真能保证最优

终局直接返回己方存活总生命值。非终局枚举每个合法联合动作，敌方行为又完全确定，每个动作对应唯一后继状态。对上述无环状态图作逆拓扑归纳，取所有后继最优值的最大值，就是当前状态的最优值。记录实现最大值的动作也可以恢复合法最优序列。

因此已有反例不能推翻新算法：新算法包括旧反例中得到5的策略，不会被迫采用得到0的旧贪心策略。

## 5. 发现的表述问题及其性质

| 问题 | 性质与影响 |
|---|---|
| 新回答未显式写 damage 全部置0 | 伪代码完整性欠缺；按每次转移新建数组理解即可。不能人为沿用上次伤害，再把新增实现错误当成模型反例 |
| NEXT 没有明确写“深复制状态” | 应补充接口语义，避免程序实现污染其他搜索分支；回答整体是函数式状态转移，不足以认定必然原地修改 |
| 移动循环更新 k，但没有单独画出快照数组 | 注释及证明已明确统一快照，应遵从其语义；顺序更新坐标并立即供后续判断读取会违反原文 |
| “至少一个仍存活目标受到伤害”措辞略含糊 | 应理解为结算前存活；结算后全部目标死亡也会让生命总量下降，不影响证明 |
| 复杂度没有注明几何运算计算模型 | O(K(m+1)^nN²)在单位代价几何运算和通常哈希假设下成立；精确代数运算的位复杂度需要另计 |
| 输出序列空间写为O(T) | 在本题n至多3时成立；若推广为可增长的n，每 tick 显式列出己方动作应写O(Tn) |
| 称小规模搜索“适合作为基准解” | 不构成所有合法输入都能快速求完的保证。指数级耗时在题干中被允许，不是输出错误的反例 |
| 网页“大模型算法”仍指旧贪心稿 | 不代表实验01的新回答。提交截图时必须标明具体版本，防止把两个算法混为一谈 |

新回答的状态数上界14(L_i+1)比必要上界1+12(L_i+1)宽松，但上界宽松不是错误。其空间O(KN)可由逐个生成动作、保存状态和最佳动作的实现达到；递归深度不超过状态数，能够被这个上界覆盖。

旧题干第11节改成攻击10、当前生命15的示例后，“第一发已足以改变第二发价值”的说明仍显得绕口，正式成稿可简化为“同 tick 的攻击均不会取消或改目标”。这属于表达改进，不是规则缺失。
