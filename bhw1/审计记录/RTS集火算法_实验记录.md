## 主实验：旧模型的贪心回答

用户补充确认：“旧的是我们用较弱的模型输出的。”据此，任务一采用旧模型的贪心算法作为真实模型输出的审计对象，沿用现有反例、错误定位与人工修正。2026-09-20新对话的精确算法另列为补充实验，不替代主实验。

| 来源项目 | 当前记录 |
|---|---|
| 算法来源 | 用户确认，来自此前使用较弱模型得到的真实回答 |
| 具体模型、版本或平台 | 待补充；“较弱模型”是用户的相对描述，不据此推测名称 |
| 早期提问日期 | 待补充，不能使用本次来源确认日期代替 |
| 早期完整题干与提问 | 待补充并与现行规则核对 |
| 早期原始回答或会话位置 | 待补充；当前《大模型版》保留为整理稿 |
| 算法决策与最优性主张是否和原文一致 | 待核对，重点检查目标优先级、虚拟血量更新、等待与全局最优主张 |
| 已验证的算法结果 | 当前整理稿在同属性反例上返回0，合法替代策略返回5，最优值为5 |

后续应核对原回答实际使用的规则，特别是题干经历过调整的统一属性、同时移动和遇敌停步条件。若当前反例符合早期题干、当前实现与原算法一致且原回答声称最优，则现有0与5的对比可直接用于主实验。若原回答只声称是启发式，低于最优值本身不能反驳它没有作出的最优性承诺。

采用用户确认的早期真实回答，不要求再让新模型犯同样的错误。补全来源信息时应保留原文与整理稿的区别，不把现行题干自动当作当年实际发送的提示词。

## 可视化使用

打开 `RTS集火算法_对局可视化.html`，选择“同属性反例”，分别播放“大模型算法”和“人工修正版”。在 tick 3 前后观察目标选择，在 tick 8—9 观察 F1 的生存和攻击差异。

网页依赖其同目录的 `rts-core.js`、`rts-scenarios.js` 和 `rts-view.js`，分享时应一并携带。全部脚本均为本地文件，无需联网。最终作业仍应提交一份 PDF，包含必要轨迹表和原始模型证据；网页及验证程序作为复核材料。
